Example:
# PROJECT DEVELOPMENT INSTRUCTIONS
## General Rules
- Follow existing project architecture.
- Read relevant documentation before implementation.
- Avoid unnecessary changes.
- Do not introduce unnecessary dependencies.
- Preserve existing functionality.
- Follow established coding conventions.
## Documentation
The docs directory contains project documentation.
Read the relevant documents before working on a feature.
If implementation changes documented behavior or architecture,
update the relevant documentation.
## Development
- Analyze before coding.
- Prepare an implementation plan.
- Obtain developer approval.
- Follow assigned responsibilities.
- Test all relevant changes.
- Report failures honestly.
## Database
- Never execute destructive operations without approval.
- Follow existing database conventions.
- Maintain data integrity.
- Update DATABASE.md when approved schema changes are implemented.
## Security

- Never expose secrets.
- Never commit environment credentials.
- Follow authentication and authorization requirements.
- Validate untrusted inputs.
## Logging
Every development task must have a unique task ID.
Update the development logs after verification.
Record failed tasks and outstanding issues.
## Final Reporting
Every completed task must include:
- Summary.
- Files modified.
- Agents involved.
- Tests performed.
- Review findings.
- Documentation updated.
- Final status.
